# Mallorca Web Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A static web game where a person plays a heads-up NLHE tournament against a TypeScript port of the Mallorca math bot.

**Architecture:** A `web/` package with pure layers `cards → equity → engine, brains` and app layers `game → ui`. The engine is a pure reducer; the bot runs in a Web Worker and returns an EV per action. The Java original produces golden fixtures that the port must match.

**Tech Stack:** Node 24, Vite, TypeScript strict, Preact, zustand, i18next, Vitest + fast-check, Playwright, ESLint + Prettier, `phe`.

**Spec:** `docs/superpowers/specs/2026-10-23-poker-web-design.md`

## Global Constraints

- All new code lives under `web/`, except `.github/workflows/web-*.yml`, root `CLAUDE.md`, root `README.md`, `.gitignore`. Java modules are not modified; the golden harness lives in `web/tools/golden/` and only reads Java sources.
- No comments in code or config, in any language. No all-caps words in UI copy. No em or en dashes as sentence punctuation in copy.
- `cards`, `equity`, `engine`, `brains` never use DOM, `Math.random`, `Date` or `performance`; randomness enters as `Rng`.
- Layer imports only downward: `ui → game → engine | brains → equity → cards`; `brains` may import types from `engine`. Enforced by ESLint `no-restricted-imports` per directory.
- Chips are integers. Starting stack 2000. Big blind schedule `[20, 30, 40, 50, 60, 80, 100, 120, 160, 200, 240, 300, 400, 500, 600, 800, 1000, 1200, 1600, 2000, 2400]`, small blind `Math.floor(bb / 2)`, level changes every 10 hands, last level holds.
- Cards in fixtures and text are two-character strings, rank `23456789TJQKA`, suit `cdhs`.
- TDD: each step writes a failing test first. Fix the code, not the rule: never loosen a tolerance, add an ignore or delete an assertion.
- Commands run from `web/` after `source ~/.nvm/nvm.sh && nvm use`. Before each commit: `npx prettier --write <paths> && npx eslint <paths> && npx tsc --noEmit && npx vitest run <paths>`.
- Conventional commits with scope = layer (`feat(engine): …`), each ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Decisions taken while planning

- `RandomVillainModel` is deterministic: it returns the probabilities the Java `RandomBot` samples from (facing a bet: fold 1/3, passive 1/3, aggressive 1/3; otherwise passive 1/2, aggressive 1/2). The golden harness wraps the same probabilities as a Java `Advisor`, so fixtures are reproducible.
- The Java `EVAdvisor` picks with `LessVarianceActionFromMap`; the port does the same.

## Review Focus

- A raise slider value outside `[min, max]` or a non-integer amount: the store clamps and rounds before `apply`, the engine throws on anything illegal. Test in Task 8.
- The human acting while the bot is thinking or during animation (double clicks, keyboard repeat): actions are ignored unless phase is `humanToAct`. Test in Task 8.
- A player with fewer chips than the big blind: posts all-in for what they have, hand runs out. Test in Task 3.
- The worker throwing or timing out: the session falls back to the in-process brain once and logs to console; the game never stalls. Test in Task 8.
- A reload mid-tournament starts a fresh start screen without errors. Covered by e2e in Task 10.
